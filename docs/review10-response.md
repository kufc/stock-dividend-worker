# 第十輪外部審查（39 條）的逐條回覆

審查報告：2026-11-27，第三版（審查端只讀程式碼，沒有執行）。這份文件是開發端的回覆：每一條查證的結果與處理。
「已修」的都有自動測試（主要在 `tests/test_review10.py`、`tests/test_regressions_review9.py`），
Windows 專屬的部分在 Wine 加安裝版內建的 Windows Python 裡跑過；**沒有任何一項在真的 Windows 上驗證過**。
報告的行號對的是原本的 1.1.0 包，修改後已經位移。

## 判讀改善路線（報告第四節）

- 第 0 步（新的獨立測試集）：沒做。同意它是前提，而且要包含原始手機照、HEIC、透明 PNG、影片與少分類的組合。
- 第 1 步做法甲：已試，不採用（見上）。做法乙、丙沒試。
- 第 2 步（從修正學習）：沒做。發行者的方向是「第一版只做同一批內」；動工前要先有第 0 步。
- 第 3、4 步：沒做。

## 這一輪另外發現的事

- 分類少（3～8 個）時，開發集上有一半左右的檔案會進「需檢查」，未知內容仍有三成被接受。這個使用情境之前沒有量過。
- 用 Wine 跑含有多個視窗測試的檔案時，偶爾有測試在建立視窗時失敗（Tk 讀不到啟動檔），單獨跑會過。原因仍然不明。
