# 預設分類的評測

這份文件回答三個問題：README 的數字怎麼來的、能不能重現、可以相信到什麼程度。
下面「自動產生」區塊裡的表格由 `python tools/evaluate.py --update-doc` 產生；`tests/test_evaluation.py`
會檢查它跟目前的程式算出來的一致，所以規則改了而文件沒更新時測試會失敗。

## 先講結論

- **資料夾裡的東西都屬於某個預設分類時**，第一名分對的比例在獨立測試集上是 **標準模型 97.5%、高精準模型 96.8%**
  （各分類 recall 的平均；Macro F1 相同）。這跟以前 README 寫的 97% 相符，而且這次是在沒調過的資料上量的。
- **高精準模型在這份測試集上沒有比標準模型好**（96.8% 對 97.5%，主要差在「人像」的 recall 75.9%）。
  752 張的差距在抽樣誤差之內（±1.2 個百分點左右），所以只能說「沒有看到優勢」，不能說它比較差；
  README 原本寫的「準確度明顯較高」沒有依據，已經拿掉。
- **資料夾裡有不屬於任何分類的東西時，一半以上會被分進某個分類**（未知類別誤接受率：標準 52.4%、高精準 58.5%）。
  「需檢查」只攔得下另一半。這是目前最大的弱點。
- 所以「不進需檢查的部分」裡分錯的比例，完全看你的資料夾有多少未知內容：
  這份測試集有 36% 是未知內容，分錯的比例是 **標準 24.7%、高精準 26.9%**；只看有答案的檔案則是 2.0%／2.2%。
- 實際上該怎麼用：先照「常出現、但還沒有這個分類」的建議把分類補齊，再相信自動整理的結果；
  沒把握的檔案現在預設放「未分類」。

## 開發集被用來調過什麼（為什麼它的成績不能當成「測試成績」）

誠實的紀錄：

1. 各分類的候選描述（`tests/manual/prompt_candidates.py`）是在收集這 1,243 張**之前**寫好的。
2. 「逐類挑選描述」試過，用對半切的方式驗證（一半挑、另一半量），沒有增益，所以沒採用。
3. 但「整組描述一起用」這個做法，是在**同一批圖片上**從 8 種做法裡選出來的。
4. 「其他東西、雜物」這個未知類別的描述，以及 50 這個門檻，是在這批與更早的 425 張上定的。

第 3、4 點代表開發集的成績有選擇偏差。所以另外收集了獨立測試集。

## 獨立測試集的紀律

- 收集時間在所有描述、規則、門檻定案之後；收集的人只做「依資料集的標記隨機抽、看縮圖刪掉標錯或兩可的」，
  定案前沒有對任何一張跑過模型。規則、亂數種子、刪了哪些、為什麼，都在 `holdout_sources.txt` 與
  `tests/manual/collect_holdout.py`（可以逐位元組重建圖片集）。
- **評測次數：1 次。** 下面的數字是第一次、也是目前唯一一次在它上面跑出來的；跑完之後沒有依它改任何描述、
  規則或門檻（第九輪審查的其他修改——分類少於 3 個時的計分、沒把握預設放未分類——都在跑它之前就定案，
  而且不影響 13 個預設分類下的這些數字）。
- 以後只要有人看著這些數字改了描述或門檻，它就不再是獨立測試集，要重新收集一份。請在這裡記錄每一次評測。

已知的限制（詳見 `holdout_sources.txt`）：

- 「城市建築」有一部分來源沒有可用的標記，等於是人工看圖挑的（45 張刪了 24 張）；「風景」也有一部分如此。
- 有些「不屬於任何分類」的組別見仁見智：運動照裡大多有人、畫作裡有人像與風景、空拍圖裡有建築、野生動物裡有大型貓科。
  這些組的誤接受率因此偏高（54%～86%），你可以自己判斷要不要把它們算成錯。
- 幾個來源解析度很低（150～256 像素）。
- 每類 51～61 張：單一類別的 precision／recall 誤差大約 ±5～10 個百分點，請不要過度解讀個別數字。
- 全部是照片與圖片，**沒有影片**；影片的取樣方式另外有限制（見 `docs/roadmap.md`）。
- 都是公開資料集的圖片，不是任何人真正的手機相簿：聊天軟體轉傳的圖、連拍、模糊照、翻拍的比例跟真實情況不同。

## 指標的定義

- **封閉**：只看「答案是某個預設分類」的檔案，取第一名，不管有沒有把握。precision／recall／F1 是一般的定義。
- **開放**：把不屬於任何分類的檔案也算進來，而且只有「沒被標成需檢查」才算分進那一類——也就是按預設值整理後，
  實際會出現在那個分類資料夾裡的東西。開放的 precision 低，代表那個資料夾裡混進了別的東西。
- **未知類別誤接受率**：不屬於任何分類的檔案裡，沒被標成「需檢查」的比例。
- **「不進需檢查的部分」分錯的比例**：所有沒被標成「需檢查」的檔案裡，分類不正確的比例（未知檔案一律算錯）。
- 人工修正時間、不同語言／裝置／來源的成績：這次**沒有量**（需要真人操作與另外的資料）。

## 門檻（50）的依據

門檻是在開發集上定的：往上調，「接受部分分錯」與「未知誤接受」下降，但「需檢查」的量與「分對被誤標」上升。
50 是「分對的檔案幾乎不會被誤標（約 1%）」的最高值附近。下面最後一張表顯示在獨立測試集上趨勢相同
（例如門檻 80：未知誤接受 19%，但三分之一的檔案要人工看）。**沒有依獨立測試集更改預設值**；
如果你的資料夾雜物多、寧可多看一些，可以在「設定」把門檻調高，這兩張表就是調整時的參考。

分類清單、模型或描述改了之後，門檻應該重新驗證：重跑 `tests/manual/dump_embeddings.py` 產生向量，
再跑 `tools/evaluate.py`。

## 重現

```
pip install numpy Pillow            # 只算指標：不需要模型
python tools/evaluate.py            # 印出下面的表格
python -m pytest tests/test_evaluation.py tests/test_real_embeddings.py
```

要從圖片重新算向量（需要下載模型，高精準模型用 CPU 約半小時）：

```
python tests/manual/collect_holdout.py --out <資料夾>
python tests/manual/dump_embeddings.py --preset standard --only-extra --per-class 0 \
    --extra-dir <資料夾> --out tests/manual/embeddings_holdout_standard.npz
```

產生這些向量時的版本：torch 2.15.0、open_clip_torch 4.2.2、transformers 5.23.0，模型的固定版本見
`media_sorter/config.py`。
