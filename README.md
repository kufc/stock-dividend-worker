# AI 媒體分類器（AI Media Sorter）

> 📄 **使用前請先閱讀**：[使用說明與免責聲明（中英對照）](使用說明與免責聲明_Usage-and-Disclaimer.txt)　｜　Please read first: [User Guide and Disclaimer (Chinese / English)](使用說明與免責聲明_Usage-and-Disclaimer.txt)

雙擊就能用的桌面程式：AI 先幫你看一遍資料夾裡的**照片與影片**，告訴你「這看起來像什麼」，
你確認（或修改）分類後，**預覽整理結果**，再一鍵**依分類複製到資料夾**（可選擇是否重新命名）。
原檔一律不動；要不要處理原檔，是整理完成之後另外、可選的動作。

- 使用 NVIDIA 顯示卡（CUDA）加速；沒有顯示卡也能用 CPU 執行（較慢）
- 分類可以**自訂、直接用中文**（例如：貓、寶寶、旅行、收據）
- 所有辨識都在**你自己的電腦**上完成，照片不會上傳到任何地方
- **辨識時嚴格離線**：載入模型與辨識的過程不連網（不檢查更新、不回報使用統計），而且不論發生什麼錯誤都不會自己改成連網。
  會連網的只有三件事，都要你明確同意：安裝時下載元件與模型、程式裡按「是」下載模型、在「設定」按「檢查並修復 AI 模型…」

## 運作流程

程式分成四個步驟，畫面上方的步驟列會顯示目前在哪一步（可以點已經完成的步驟回頭看）：

```
① 選擇資料夾 ──▶ ② 檢查分類 ──▶ ③ 預覽整理結果 ──▶ ④ 完成
   看到圖片／影片    左邊清單＋右邊大預覽    輸出位置、檔名、     結果、失敗重試、
   數量，開始辨識    看縮圖、把分錯的改掉    整理前後對照         之後（可選）的處理
```

整理後的結果（預設保留原檔名；選「分類＋序號」時會像下面這樣）：

```
手機照片\
└─ 已分類\
   ├─ 貓\        貓_001.jpg、貓_002.heic、貓_003.mp4 ⋯
   ├─ 風景\      風景_001.jpg ⋯
   └─ 螢幕截圖\  螢幕截圖_001.png ⋯
```

## 系統需求

| 項目 | 需求 |
| --- | --- |
| 作業系統 | Windows 10 / 11（64 位元）。**只支援 Windows**：檔案安全的強制保護（握著檔案時別的程式不能改、不能刪）只有 Windows 有 |
| Python | 用安裝程式（setup.exe）安裝時**已經內建，不需要另外安裝**；只有「免安裝版」（ZIP＋`install.bat`）才需要自己安裝 **Python 3.12**（一定要 3.12：安裝時會逐一核對下載套件的雜湊，核對清單是替 3.12 產生的） |
| 顯示卡（選配） | NVIDIA 顯示卡，並安裝最新版驅動程式；RTX 50 系列也支援 |
| 記憶體 | 8 GB 以上；「高精準」模型建議 12 GB 以上 |
| 硬碟空間 | 約 12 GB（PyTorch 約 5 GB＋AI 模型 1.5～5 GB＋暫存）；整理時另需與照片相同大小的空間（先複製） |

## 安裝（建議：安裝程式）

1. 雙擊 **`AI-Media-Sorter-Setup-版本.exe`**，跟著精靈操作
   - **現況：安裝程式沒有數位簽章**（專案目前沒有程式碼簽章憑證）。所以 Windows SmartScreen 會顯示
     「Windows 已保護您的電腦」，而且 Windows 無法替你確認這個檔案是誰發行的、有沒有被改過。
     這個警告是正確的，不是誤報。要不要執行請自己判斷：只從你信任的來源取得安裝檔；
     可以向提供者索取檔案的 SHA-256，用 `certutil -hashfile 檔名 SHA256` 核對；
     不放心的話，改用下面的免安裝版（看得到全部原始碼，由你自己的 Python 執行）。
     確定要執行時，SmartScreen 的畫面上按「其他資訊」會出現執行的按鈕
   - 先閱讀並接受使用說明與免責聲明，再選擇資料夾與是否建立桌面捷徑
   - **不需要系統管理員權限**，只安裝給目前的使用者；預設裝在 `%LOCALAPPDATA%\Programs\AI Media Sorter`。
     不論選哪個位置，程式一定會放在名為「AI Media Sorter」的子資料夾裡
2. 安裝程式最後會自動偵測你的 NVIDIA 顯示卡，下載對應 CUDA 版本的 PyTorch 與 AI 模型
   （數 GB，請耐心等候；進度在另一個黑色視窗，請不要關閉）。失敗時可以按「重試」，或先完成安裝，
   之後從開始功能表執行「**修復**」補裝
3. 從開始功能表（或桌面捷徑）開啟「AI 媒體分類器」

- 程式檔案（含內建 Python）在安裝資料夾；**你的設定、整理紀錄與錯誤紀錄**放在 `%LOCALAPPDATA%\AI Media Sorter`，
  跟程式檔案分開，重新安裝或升級不會被蓋掉。同一個地方的 `analysis-cache\` 是工作資料庫與縮圖快取（見下面「接續上次的工作」）
- 只寫入目前使用者的登錄項目（讓「設定 → 應用程式」能列出並解除安裝它），不建立服務、不開機自動啟動
- 給管理員：`setup.exe /S` 靜默安裝（`/D=資料夾` 指定位置、`/SKIPDEPS` 略過下載）

### 免安裝版（ZIP＋install.bat）

不想用安裝程式時，可以用免安裝版（需要自己先安裝 64 位元的 **Python 3.12**，其他版本會被拒絕，安裝時勾選
**Add python.exe to PATH** 與 **tcl/tk and IDLE**）：

1. 下載這個專案（GitHub 綠色的 **Code → Download ZIP**；或用 `git clone`），在 ZIP 上按右鍵 →「**全部解壓縮**」，
   放在一般資料夾（例如 `C:\AI媒體分類器`），避開 OneDrive 同步資料夾
2. 雙擊 **`install.bat`**：建立獨立環境（`.venv` 資料夾）、依顯示卡安裝對應的 PyTorch、下載 AI 模型並測試
3. 看到「安裝完成！」後，雙擊 **`start.bat`** 開啟程式

> 第一次安裝需要下載數 GB 的檔案，請耐心等候。

### 安裝時 pip 出現「access violation」？

新版 pip（24.2 以上）預設用 Windows 憑證元件驗證 HTTPS，少數電腦上它會當掉（畫面上出現
`OSError: exception: access violation writing 0x…`）。安裝程式會先實際測試，偵測到就自動改用 pip 內建的憑證，
並在下載失敗時再自動重試一次；如果還是失敗，通常是防毒、VPN 或代理軟體干擾，暫時關閉後再試。

## 使用方式

雙擊 **`start.bat`** 開啟程式（第一次使用若還沒安裝，會自動先執行安裝）。

1. **選擇資料夾**：按「選擇資料夾…」（可勾選「包含子資料夾」），畫面會顯示找到幾張圖片、幾支影片、
   幾個不支援而會被略過的檔案，以及 AI 模型是否需要下載。確認後按「開始辨識 N 個檔案」
   - 「要分成哪些類別」會列出目前的分類；分類越貼近你的照片內容，分得越準。按「修改分類…」可以先改（之後再改也不用重新辨識）
2. **檢查分類**：AI 已經把每個檔案分好，不用逐一確認。左邊是分類清單（含數量），中間是該分類的縮圖格，右邊是目前檔案的大預覽
   - 點左邊的一個分類，看 AI 放進去的檔案；看到分錯的，點它（Ctrl 點加選、Shift 點連選、Ctrl+A 全選），再按下面正確的分類按鈕，立刻生效
   - **「需檢查」** = AI 沒把握的檔案集中在這裡（縮圖右上角有「？」）：第一名分數不到門檻的，以及比起任何分類更像「其他東西」的。把它們指定到正確的分類；你沒指定的，預設會放到「未分類」資料夾（步驟 3 可以改）
   - 縮圖格上方的「常出現、但還沒有這個分類」：很多檔案明顯是某種東西（例如聊天截圖）而你沒有這個分類時會列出來，點一下就新增並重新判斷（不用重新辨識）
   - 進到某個分類時，**AI 最沒把握的排在最前面**（分錯的通常在這裡）；按「排序」可以改回原本的順序
   - 跟檔案總管一樣：在空白處**拖曳框選**、把選取的縮圖**拖到左邊的分類**（或「已略過」）、**按右鍵**叫出選單（分到某類、略過、放大檢視、開啟檔案、開啟所在資料夾）
   - 下面的按鈕：**分類按鈕**（數字鍵 1～9、0）、**採用 AI 建議**（Enter）、**略過，不整理**（S）、**新增分類…**（選取中的檔案會直接分到新分類）、**撤回上一步**（Ctrl+Z）
   - 右邊顯示大預覽、AI 覺得像的前三名（只顯示名次與「領先多少」的說明；分數是分類之間的相對值，**不代表正確率**）與「AI 還看到」的東西（點一下可以當作新分類）；按兩下縮圖可放大檢視（影片會用電腦的播放程式開啟），空白鍵也可以放大
   - 縮圖右上角的 ✓ 是你指定過的分類；縮圖大小可選小／中／大，下次開啟會記住
   - 辨識還沒跑完也可以先看、先改，結果出來後不會蓋掉你的選擇
   - 視窗比較窄時會收起右邊的預覽（仍可按兩下縮圖放大檢視）
3. **預覽整理結果**：不會動到任何檔案，只是讓你看清楚接下來會發生什麼
   - 顯示**真正的輸出路徑**、需要的磁碟空間與剩餘空間，以及「整理前後對照」表
   - 檔名：預設**保留原檔名**；也可以選「分類＋序號」「日期＋分類＋序號」或自訂格式，對照表會即時更新
   - AI 分好的加上你指定的檔案都會整理；略過與讀取失敗的不會
   - AI 沒把握、你也沒改的檔案可以選擇：放到「未分類」資料夾（預設）／仍然依 AI 建議放進分類／這次不整理
   - 按「開始複製 N 個檔案」才會開始；複製中可按「完成目前檔案後停止」，已複製好的會保留
4. **完成**：顯示成功與失敗的數量
   - 有失敗的檔案時，會用白話說明「發生什麼事、可以怎麼做」，處理後按「重試」，已複製好的不會重做；技術細節預設收起來
   - 按「開啟輸出資料夾」檢查結果
   - 「之後的處理（可選）」：原檔都還在原位，不處理也沒關係。想處理時，到「整理紀錄」頁選一批整理：
     - **移除這次建立的複本…**：不滿意時使用，複本移到資源回收筒，原檔不受影響
     - **將這批原檔移到回收筒…**：確認複本沒問題後才用。確認視窗會列出來源資料夾、輸出資料夾與**每一個**檔案
       （可搜尋），來源跟你目前選的資料夾不同時會顯示警告，預設按鈕是「取消」
     - 原檔會移到 Windows 的**資源回收筒**，檔名會多一個標記（例如 `IMG_1234 (整理前).jpg`），還原後改回即可
     - 只有跟複本內容完全相同的原檔才會移除；複本不見或被改過的，原檔會保留
     - 原檔正被其他程式開著時不會移除，會列為失敗，關掉那個程式後再做一次即可
     - 確認之後、執行之前，如果紀錄檔被改變，程式會拒絕執行並請你重新檢視

畫面上方還有「整理紀錄」「分類設定」「設定」「說明」。「說明」會打開使用說明與免責聲明。

### 接續上次的工作

辨識結果與你的修改都會存到磁碟上（使用者資料夾裡的 `analysis-cache\`：一個 SQLite 資料庫加上縮圖檔）：

- 每個檔案辨識完就寫入；你指定分類、略過、撤回，也是當下就寫入
- 關掉程式、當機、被工作管理員結束之後，選同一個資料夾再按「開始辨識」就會接續：
  **沒變過的檔案直接沿用結果（不讀檔、不進模型），你改過的分類會套回來，只辨識新增或變更的檔案**
- 「沒變過」的定義：路徑、檔案大小、修改時間都一樣，而且模型（含固定的版本）、前處理版本、影片取樣張數也一樣；
  任何一項不同就重新辨識。檔案內容換過的話，之前對它做的決定也不再套用
- 分類的分數不保存，而是用保存的向量跟「目前的分類清單」重算，所以改了分類清單也不會用到舊分數
- 縮圖放在磁碟上，記憶體裡只留檔名（以前是把每張縮圖的 JPEG 都留在記憶體，十萬張就是好幾 GB）
- 這些是從你的照片算出來的資料（含照片的縮小圖），只存在你的電腦上。「設定」裡的「清除保存的辨識結果…」可以清掉；
  解除安裝時的處理方式見下面「解除安裝」
- 資料庫壞掉時會把壞的那份改名留著、重新建立，最壞情況只是重新辨識；不影響任何照片
- 限制：整台電腦突然斷電時，最後幾筆可能沒寫進磁碟（那幾個檔案會重新辨識，資料庫不會壞）

### 檔案安全

整理採用「**先複製、確認後再移除原檔**」，設計目標是：**不論哪個環節出錯，都不會讓任何一份照片從磁碟上消失。**

- 整理只會複製，原檔不動；撞名就自動換下一個編號，絕不覆蓋任何既有檔案
- 複製時先寫成不會撞名的暫存檔，寫完後先確實寫入磁碟（fsync），再把寫進去的內容**讀回來跟原檔比對**，
  確認無誤才改成正式檔名；磁碟滿了、寫入出錯或複製途中原檔被改寫，都不會留下不完整的檔案
  （代價：目的地多讀一次，複製大檔會慢一些）
- 每一次刪除（復原時移除複本、移除原檔）都要求「**另一份內容逐位元組相同的檔案仍然存在**」，
  而且刪除一律送到資源回收筒。所以就算整理紀錄（`logs\整理紀錄_*.csv`）寫到一半、被修改或被放回舊的，
  最壞情況只是某個檔案沒被處理，不會遺失資料
- 刪除的順序是「比對 → 先在同一個資料夾內改名 → 用『禁止其他程式寫入』的方式開啟**兩份**檔案 →
  握著它們再比對一次、送資源回收筒 → 最後才放開」：
  - 從比對到送出為止，要移除的那一份和留下的那一份都不能被任何程式修改
  - **留下的那一份**還多一層：握著它的期間，其他程式不能刪除它、不能改名、也不能拿別的檔案取代它
    （要移除的那一份必須允許刪除，資源回收筒才搬得走，所以兩份的保護方式不同）；送出前會再確認它仍是同一個檔案
  - 任何一份已被其他程式（例如照片編輯器、同步程式）開著寫入時，程式回報「使用中」並保留檔案
  - 改名後，照原路徑存檔的程式只會產生新檔，不會動到要送出的那一份
  - 限制：這些強制保護只有 Windows 有；在其他系統上只做得到改名、第二次比對與送出前的檢查
- **沒有資源回收筒的磁碟**（網路磁碟機／NAS、隨身碟、記憶卡）：Windows 對這些地方的檔案「送回收筒」其實是直接永久刪除。
  程式會先看檔案在哪一種磁碟上，不會把它當成有回收筒：
  - 原檔在這種磁碟上：**不移除**，確認視窗與結果都會寫明原因，原檔與複本都保留（要刪請自行在檔案總管刪除）
  - 複本在這種磁碟上（按「移除這次建立的複本」時）：不刪除，改搬到輸出資料夾裡的 `復原移除\日期_時間\`
  - 判斷不出磁碟種類時，一律當成沒有回收筒
- **回收筒被關掉、或檔案比回收筒大**：Windows 這時也會直接永久刪除，而且不會問。程式會先讀這個磁碟的回收筒設定
  （「不要將檔案移到資源回收筒」、系統管理原則、容量上限；沒設定過就用 Windows 的預設容量估算），
  會變成永久刪除的原檔一律不移除並說明原因（常見情況：很大的影片檔）；設定讀不出來時也當成沒有回收筒
- 另外兩種也會被擋下：**路徑太長**（超過 240 個字元，回收筒放不進去）；檔案在**被搬到別處的「圖片／文件」資料夾**裡時，
  那個資料夾自己的回收筒設定也要過
- 這些都是「先查 Windows 的設定再決定」，規則是我們自己列的，有可能漏；真的 Windows 上的實測清單見 `docs/release-checklist.md`
- 上次複製到一半被強制結束留下的暫存檔（`*.ams-partial`），下次複製到同一個資料夾時會清掉（只清本程式自己的、超過一小時的）
- 圖片檔看起來沒傳完（缺檔尾）時，照樣辨識看得到的部分，但一律放進「需檢查」並說明
- 輸出資料夾不能就是來源資料夾
- 確認視窗會列出這次要處理的**每一個**檔案（可搜尋、可捲動，不省略），標明哪些會處理、哪些不符合條件而保留，
  以及來源與輸出資料夾；紀錄的來源資料夾跟你目前選擇的資料夾不同時，會顯示警告
- 你確認的清單，就是實際執行的清單：確認之後紀錄檔若被改變，程式會拒絕執行
- **整理紀錄不是安全邊界**：紀錄沒有簽章，來源與輸出資料夾也寫在紀錄裡，能修改紀錄的人可以一起修改。
  真正的保護是「另一份內容相同的檔案必須存在」、一律送到資源回收筒，以及確認視窗的完整清單——
  按下確認前請看一下清單
- 紀錄檔無法讀取或是空的時，會給出說明並可把它移到旁邊（改名為 `無法讀取_…`），以便處理更早的紀錄
- 兩個路徑其實指向同一個檔案（大小寫不同、目錄連接點）時，不會被當成「另一份」
- 沒有安裝資源回收筒套件（send2trash）時：移除複本會把複本搬到 `logs\復原移除\`，移除原檔則完全不動作
- 圖片與影片畫面的像素數上限為 3 億（約涵蓋 200MP 手機照片）。這是硬上限：程式在解碼前先看檔頭的寬×高，
  超過就不讀取，顯示為「無法讀取」並說明原因；縮圖、預覽、放大檢視與影片畫格都走同一個檢查
- 掃描時會跳過資源回收筒、`System Volume Information`、NAS 縮圖（`@eaDir`）與系統檔

### 「AI 還看到這些」

除了你設定的分類，AI 也會從內建的 150 個常見詞彙中找出畫面裡的東西（例如「沙發」「夕陽」「聊天截圖」），
點一下就能把它**新增為分類**，AI 會立刻重新判斷所有檔案（不需要重新讀檔，只要幾秒鐘）。

## 分類設定

按「分類設定」（或第 1 步的「修改分類…」）可以新增、刪除、排序分類。每個分類有：

- **名稱**：也是資料夾名稱與檔名的一部分
- **補充說明**（選填，每行一種說法）：告訴 AI 這一類長什麼樣子，中文或英文皆可，多寫幾種說法比較準
- 「加入常用分類」可以一按就加入寶寶、旅行、海報廣告、商品、圖表等分類，並自動帶入說明

預設分類：人像、合照、貓、狗、風景、城市建築、美食、花草植物、交通工具、螢幕截圖、文件收據、動漫插畫、迷因梗圖。
每個預設分類內建十幾句說明。實測成績（完整的表格、定義、限制與重現方式見 [`docs/evaluation.md`](docs/evaluation.md)）：

| 在獨立測試集上（1,176 張，來源與調整用的那一批完全不同，只用來報告） | 標準模型 | 高精準模型 |
| --- | ---: | ---: |
| 檔案確實屬於某個預設分類時，第一名分對的比例（各分類平均） | 97.5% | 96.8% |
| 檔案**不屬於任何分類**、卻沒被標成「需檢查」的比例 | 30.4% | 32.3% |
| 「不進需檢查的部分」分錯的比例（這份測試集有 36% 是不屬於任何分類的檔案） | 16.3% | 17.2% |

白話：**你的資料夾裡都是這些分類的東西時，分得很準；混了別的東西時，那些東西大約有三成會被分進某個分類，**
其餘會進「需檢查」，預設放到「未分類」資料夾。所以請先看縮圖格上方「常出現、但還沒有這個分類」的建議把分類補齊。
高精準模型在這份測試集上沒有比標準模型準，所以預設一律用標準模型。
（後兩列是把「需檢查」門檻從 50 調到 70 之後的數字；調整的決定受了這份測試集影響，所以這兩列可能略為樂觀，
細節與原本門檻 50 的數字見評測文件。）
調整描述與門檻時用的是另一批 1,243 張（`tests/manual/photo_sources.txt`），它的成績有選擇偏差，只當對照。
`python tools/evaluate.py` 可以用 repo 裡的向量檔重算所有數字，不需要下載模型。
從舊版升級時，你沒改過的預設說明會自動換成新的，
改過的與自己新增的分類不會被動到。

分類清單存在 `categories.json`，想備份或分享給別人時複製這個檔案即可。

## 重新命名樣式

| 代碼 | 意義 | 範例 |
| --- | --- | --- |
| `{分類}` | 分類名稱 | 貓 |
| `{序號}` | 同一分類內依拍攝時間排序的編號 | 001 |
| `{日期}` | 拍攝日期（照片 EXIF → 影片資訊 → 檔案修改時間） | 20240503 |
| `{原檔名}` | 原本的檔名（不含副檔名） | IMG_2031 |

例如 `{分類}_{日期}_{序號}` → `貓_20240503_001.jpg`。撞名時會自動換下一個編號，不會覆蓋任何檔案。

## 設定

| 設定 | 說明 |
| --- | --- |
| AI 模型 | 預設是**標準模型**。「高精準」要自己選：它大四倍、需要顯示卡，但在獨立測試集上沒有比較準 |
| 影片取樣畫面數 | 每支影片平均擷取幾張畫面來判斷（預設 8） |
| 需檢查的門檻 | 第一名的相對分數低於此值的檔案，放進「需檢查」（預設 70，滿分 100）。分數是「在目前的分類之間相對最像誰」，不是判斷正確的機率；這個預設值的依據見 `docs/evaluation.md` |
| 每批處理張數 | 一次送進顯示卡的張數；出現記憶體不足時請調低 |

| 模型 | 首次下載 | 特色 |
| --- | --- | --- |
| 標準（xlm-roberta-base-ViT-B-32） | 約 1.5 GB | 速度快，CPU 也跑得動 |
| 高精準（xlm-roberta-large-ViT-H-14） | 約 5 GB | 模型大四倍、需要顯示卡；在獨立測試集上**沒有**比標準模型準（見 `docs/evaluation.md`），不確定時用「標準」即可 |

兩者都是 [LAION](https://laion.ai/) 的多語言 CLIP 模型（透過 [OpenCLIP](https://github.com/mlfoundations/open_clip)），
支援中文分類名稱。模型從 Hugging Face 下載，存放在 `%USERPROFILE%\.cache\huggingface`
（想放到其他磁碟，可設定環境變數 `HF_HOME`）。

**模型與連網的三種狀態**（程式不會自己在它們之間切換）：

| 狀態 | 什麼時候 | 會不會連網 |
| --- | --- | --- |
| 嚴格離線 | 平常開啟程式、載入模型、辨識 | 不會。載入前先核對模型檔（固定版本、大小、SHA-256）；缺檔、損壞、記憶體不足、套件版本不合等任何錯誤，都只會顯示原因與修法，不會改成連網重試 |
| 你同意後下載 | 安裝的最後一步；或辨識時模型不能用，程式問你、你按「是」 | 只連 huggingface.co，只下載 `media_sorter/config.py` 列出的固定版本檔案，下載完核對雜湊，然後回到離線 |
| 你要求修復 | 「設定」→「檢查並修復 AI 模型…」，或 `python -m media_sorter --repair-model` | 先重新計算每個檔案的雜湊；都正確就不連網，有缺損才重新下載那些檔案 |

`python -m media_sorter --verify-model` 只核對、不連網。這個行為有自動測試把 socket 全部擋掉來驗證
（`tests/test_netpolicy.py`，含真的 PyTorch／OpenCLIP 與真的模型檔）。

AI 一定會把檔案歸到「最像」的分類，所以分類太少時，不相關的照片也會被硬塞進去。
建議至少設定 3 個分類。AI 一定會把每個檔案放進最像的一類：不屬於任何分類的檔案，在獨立測試集上大約七成會被放進「需檢查」，其餘三成會被放進某個分類——所以縮圖格上方的「常出現、但還沒有這個分類」建議很重要，照著加上分類之後，那些檔案才會有地方去。

## 解除安裝

**用安裝程式安裝的版本**：Windows「設定 → 應用程式 → 已安裝的應用程式」選「AI 媒體分類器」→ 解除安裝
（或開始功能表裡的「解除安裝」）。精靈會問你要不要一併移除下面的個人資料，**預設全部保留**：

| 項目 | 說明 |
| --- | --- |
| 設定與分類清單（`settings.json`、`categories.json`） | 移除後重新安裝會回到預設分類 |
| 整理紀錄與錯誤紀錄（`logs\` 裡的檔案） | 移除後，無法再用本程式移除複本或處理原檔（檔案本身不受影響）；有還沒處理完的紀錄時會提醒 |
| 保存的辨識結果與縮圖快取（`analysis-cache\`） | 內含你照片的縮小圖與你改過的分類。**勾選上面兩項的任何一項時一併移除**；都不勾就留在電腦上 |
| 本程式用的 AI 模型檔案（Hugging Face 快取） | 快取可能跟其他程式共用，只會刪本程式的兩個模型資料夾 |

- 程式檔案與內建 Python、捷徑、登錄項目一定會移除；安裝資料夾本身**只有在已經空了**時才會移除，
  裡面若有你自己放的東西就保留
- 程式還開著時，安裝、升級與解除安裝都會拒絕執行
- 給管理員：`uninstall.exe /S` 靜默解除安裝（預設保留個人資料；`/REMOVE_SETTINGS`、`/REMOVE_LOGS`、`/REMOVE_MODEL` 一併移除；前兩個任一個都會連同 `analysis-cache\` 一起移除）。
  需要結束代碼時加 `_?=安裝資料夾`（放在最後、不加引號）：0＝完成、5＝程式正在執行（什麼都沒刪）；
  這種方式下 `uninstall.exe` 本身會留在資料夾裡，請在之後刪除。安裝程式 `/S` 的結束代碼：0＝完成、
  2＝AI 元件下載沒完成（之後可從開始功能表「修復」）、5＝程式正在執行

**免安裝版**：關閉程式後雙擊 **`uninstall.bat`**。它會先列出每一項會做什麼、多大，你輸入 **Y** 才會開始：

| 項目 | 預設 | 說明 |
| --- | --- | --- |
| 程式運作環境（`.venv`：Python、PyTorch 等套件，約數 GB） | 移除 | 要再用時重新執行 `install.bat` |
| 設定與分類清單、整理紀錄與錯誤紀錄、保存的辨識結果與縮圖快取、AI 模型檔案 | 保留，各自詢問後才移除 | 同上表 |

程式資料夾本身不會被刪除，不需要時請自行刪除整個資料夾。

**兩種版本都絕對不會動**：你的照片與影片、整理輸出的資料夾（例如「已分類」）、資源回收筒、`logs\復原移除` 裡的檔案
（沒有資源回收筒時被搬開的複本，是你的檔案），以及程式資料夾以外的其他東西。

安全設計：

- 只會刪清單裡的項目，每一項在刪除前都會再確認「確實在預期的位置、名稱完全符合」；不接受自訂刪除路徑
- 使用者資料夾必須有本程式的標記檔才會處理；找不到本程式的檔案、或資料夾是磁碟根目錄／使用者資料夾時拒絕執行
- 連結（符號連結、目錄連接點）只移除連結本身，不會跟著刪掉它指向的內容
- 任何一項失敗都會如實回報，不會假裝成功；可以關掉占用檔案的程式後再執行一次
- 免安裝版進階：`python -m media_sorter.uninstaller --dry-run` 只列出會做什麼；`--yes` 不詢問（預設只移除 `.venv`），
  搭配 `--remove-settings`、`--remove-logs`、`--remove-model` 指定其他項目

安裝版只寫入目前使用者的兩個登錄項目並在解除安裝時移除；免安裝版不寫登錄檔。都不建立服務或開機自動啟動項目；
留在電腦上的只有程式檔案、你的使用者資料、AI 模型快取，以及 pip 自己的下載快取（可用 `pip cache purge` 清除）。

## 疑難排解

| 狀況 | 解決方式 |
| --- | --- |
| 防毒軟體（例如卡巴斯基）說「無法檢查 huggingface.co 的加密連線」 | 防毒軟體的加密連線檢查跟下載元件不相容（不是病毒警告）。選「新增至排除項目」後再試一次；可能還會出現模型下載主機（名稱結尾是 `xethub.hf.co` 或 `hf.co`，例如 `cas-server.xethub.hf.co`、`us.aws.cdn.hf.co`）、`pypi.org`、`files.pythonhosted.org`、`download.pytorch.org`、`download-r2.pytorch.org`。模型下載完成後程式就不再連到這些網站 |
| 辨識時狀態列顯示「CPU（未偵測到可用的 NVIDIA 顯示卡）」 | 更新 NVIDIA 驅動程式後，重新執行 `install.bat` |
| 雙擊 `start.bat` 沒反應 | 程式可能已經開著（看工作列）；或查看 `logs\error.log`、`logs\console.log`，也可以在命令提示字元執行 `.venv\Scripts\python -m media_sorter` 看錯誤訊息 |
| 安裝時說「程式正在執行中」 | 先關閉 AI 媒體分類器視窗再執行 `install.bat` |
| 安裝時說缺少視窗元件（tkinter） | 重新執行 Python 安裝程式 → Modify → 勾選「tcl/tk and IDLE」 |
| install.bat 顯示找不到 Python | 安裝 Python 時要勾選「Add python.exe to PATH」 |
| PyTorch 安裝失敗 | Python 版本可能太新，改裝 Python 3.12 後刪除 `.venv` 資料夾再執行 `install.bat`（安裝程式會優先選 3.12） |
| 顯示卡記憶體不足（out of memory） | 「設定」中把「每批處理張數」調低，或改用「標準」模型 |
| 某些影片「無法讀取」 | 檔案可能損毀、編碼特殊，或是純錄音檔；可手動選分類或略過 |
| 顯示「AI 計算結果異常（NaN）」 | 少數顯示卡的半精度計算不穩定，程式會自動改用 fp32；若仍出現請改用「標準」模型 |

沒有安裝 torch 時，需要真模型的測試會自動略過；Windows 專屬的測試（檔案鎖、磁碟種類）在其他系統略過，
可以用 Wine 加安裝版內建的 Windows Python 執行（`installer/test_in_wine.sh` 的開頭有做法）。
還沒做的功能見 [`docs/roadmap.md`](docs/roadmap.md)；公開發行前必須由發行者完成的事（真機驗證、簽章、授權確認）見
[`docs/release-checklist.md`](docs/release-checklist.md)。

測試使用假的模型（依顏色分類），不需要下載 AI 模型或顯示卡；`tests/test_app.py` 會實際開啟視窗跑完整流程，
`tests/test_regressions_*.py` 是對抗測試找到的問題所對應的回歸測試。

### 建置 Windows 安裝程式

```bash
pip install py-rattler pillow          # 取得內建 Python（conda-forge，含 tkinter）用
sudo apt install nsis                  # Windows 上改裝 NSIS 並加入 PATH
python installer/build_installer.py --publisher "你的公司名稱"
# → dist/AI-Media-Sorter-Setup-版本.exe
```

- 安裝程式內建 64 位元 Python 3.12（conda-forge 的 Windows 版，含 tkinter 與 pip），使用者不需要自己安裝 Python；
  安裝的最後一步才在使用者的電腦上依顯示卡下載 PyTorch 與 AI 模型。內建套件清單在安裝後的 `app\\RUNTIME-PACKAGES.txt`
- 在 Linux 上可以用 Wine 實際跑一次「安裝 → 使用 → 解除安裝」驗證：`installer/test_in_wine.sh dist/AI-Media-Sorter-Setup-版本.exe`
- 程式圖示與安裝精靈圖片由 `python installer/make_icon.py` 產生（原創圖形，無第三方素材）

### 更新相依套件與模型的版本

所有版本都是固定的，升級是刻意的動作：

| 東西 | 固定在哪裡 | 怎麼更新 |
| --- | --- | --- |
| 直接用到的套件 | `requirements.txt`（`==`） | 改版本號 → `python tools/update_lock.py` |
| 所有間接相依套件＋每個檔案的 SHA-256 | `requirements.lock`（Windows x64、Python 3.12） | `python tools/update_lock.py`（需要 `uv`）自動產生，不要手改 |
| PyTorch／torchvision | `media_sorter/installer.py` 的 `TORCH_PINS`：每個下載站（cu128／cu126／cpu）各一組版本與 SHA-256 | 到 `https://download.pytorch.org/whl/<代號>/torch/` 找 `cp312-win_amd64` 的檔案，版本與網址後面的 `sha256` 一起更新；torchvision 要選跟 torch 相容的版本 |
| AI 模型與斷詞器 | `media_sorter/config.py` 的 `MODEL_PRESETS`：Hugging Face commit、每個檔案的大小與 SHA-256 | `python tools/update_model_pins.py --latest` 印出新的內容 |
| 內建的 Python | `installer/build_installer.py`（3.12） | 換版本時鎖定檔與 `TORCH_PINS` 的雜湊都要重新產生 |

更新任何一項之後：跑完整的測試；換 PyTorch、open_clip、transformers 或模型時，還要重跑
`tests/manual/dump_embeddings.py` 與 `python tools/evaluate.py --update-doc`，確認 `docs/evaluation.md` 的數字。
安裝時的行為：安裝版（內建 Python 3.12）用 `pip --require-hashes` 核對每個下載檔；
免安裝版如果用的是別的 Python 版本，只固定 `requirements.txt` 的版本、不核對雜湊（安裝時會講）。
目前**沒有**的：相依成分清單（SBOM）、有回復能力的自動更新、已簽章的發行檔（見 `docs/roadmap.md`）。

**數位簽章（目前沒有；公開發行前應該要有）**：沒有簽章時，Windows SmartScreen 會顯示「已保護您的電腦」。取得程式碼簽章憑證
（.pfx）後，用環境變數提供憑證，再加 `--sign` 建置，`setup.exe` 與安裝後的 `uninstall.exe` 都會被簽章：

```bash
export MEDIA_SORTER_SIGN_PFX=/安全的位置/憑證.pfx
export MEDIA_SORTER_SIGN_PASSWORD=憑證密碼          # 只從環境變數讀取，不會出現在指令列或建置紀錄
export MEDIA_SORTER_SIGN_TIMESTAMP=http://timestamp.digicert.com   # 預設值；憑證供應商有指定時請照它的
python installer/build_installer.py --publisher "你的公司名稱" --sign
```

Windows 上使用 Windows SDK 的 `signtool`，Linux 上使用 `osslsigncode`（`apt install osslsigncode`）。
EV 憑證或雲端簽章服務（例如 Azure Trusted Signing）請依供應商說明調整 `installer/sign.py`。
授權條款、發行者名稱與隱私權聲明也請依你的實際情況補上。
